## 2. Purpose and Acceptance Boundary

Contract 8 defines the complete semantic contract for unseen-space claim evaluation inside one eligible Contract-7 meaningful-partial-scene SemanticCase.

Contract 8 owns:

- a closed, versioned, language-neutral unseen-claim vocabulary;
- explicit allowed-claim expectations and prohibited-claim expected-absence records;
- untouched raw mechanism assertion identities and evaluator-normalized atomic produced-claim identities with explicit transformation provenance;
- immutable expected-versus-produced comparison records;
- deterministic claim classification, applicability, precedence, duplicate handling, contradiction handling, lifecycle, sealing, adjudication, exclusion, replacement, localization, validation, failure and escalation;
- Contract-8 semantic conformance facts;
- a strict one-emitted-assertion-to-one-unit projection boundary for the ETAP-owned `PARTIAL-CLAIM-CONFORM` mechanism-output metric.

Contract 8 does not own or redefine ETAP metric IDs, numerator, denominator, threshold, zero-denominator handling, confidence interval or statistical method. Missing required expectations and absent prohibited claims remain Contract-8 semantic comparison facts unless an accepted ETAP successor creates a separate recall/absence metric.

Contract 8 does not own final JSON, wire names, database/API/TypeScript schemas, fixture architecture, metric thresholds, population membership, source acquisition, annotation execution, provider/model invocation, implementation, training, Security Architecture, or Diagnosability Architecture.

1. sealed ground-truth allowed expectations;
2. sealed ground-truth prohibited expected-absence records;
3. provider/mechanism-produced atomic claims;
4. immutable comparisons;
5. adjudication/replacement/jurisdiction audit records.

No single identity may serve more than one role. The semantic model is provider-neutral and implementation-neutral. Semantic component names in this document are conceptual labels, not final Contract-10 property names.

Closed requirement model:

- Revision 1 defines no optional requirement level.
- Every allowed expectation that exists is `c8.requirementlevel.001`.
- Every prohibited expectation is `c8.requirementlevel.002`.
- Any record carrying another requirement identity, or relabelling a required expectation as optional, is invalid.
- prohibited does not mean merely absent: every eligible case carries exactly twelve explicit pre-output prohibited expected-absence records, one for each prohibited code 004, 009–015, and 016–019;
- required absence is evaluated by comparing that prohibition record with produced claims under §12.1 and §16;
- an allowed code with a false predicate is `c8.applicabilitydisposition.003`; no expectation/comparison record is created for that code;
- inapplicability is never a final result for an eligible required expectation or prohibition;
- required record absence is a Contract-8 semantic FAIL; there is no Not Scorable result. It is not projected into the ETAP mechanism-output denominator unless an accepted ETAP successor explicitly creates such a metric.

### 12.1 Matching keys

Allowed expectation matching key:

`RoomCase identity + primary claim code + subject identity + target/complement identity + normalized locus identity`

This key identifies one allowed atomic proposition. Distinct loci remain distinct. A repeated proposition from several views is a duplicate occurrence, not several independent claim credits.

Prohibited expectation matching key:

`RoomCase identity + primary prohibited claim code`

A sealed prohibited-claim expectation is case-scope and acts as a code-scoped wildcard for subject, target/complement, and locus. Every produced atomic claim in the same RoomCase whose deterministic primary code equals that prohibited code matches the corresponding prohibition record. Produced subject, target and locus remain mandatory diagnostics and never prevent the prohibited match.

Comparison cardinality is per produced normalized claim, never per aggregate group:

- an allowed expectation with zero matches receives exactly one comparison with no produced identity and c8.comparisonresult.002;
- an allowed expectation with one or more matches receives one comparison per matched produced claim; the earliest emitted raw assertion and then lowest normalized interpretation identity is the canonical candidate for the ordinary pass/fail result, while additional same-key final-output claims receive c8.comparisonresult.012 unless a higher §17.2 defect applies;
- a prohibited expectation with zero matches receives exactly one comparison with no produced identity and c8.comparisonresult.003;
- a prohibited expectation with one or more matches receives one separate comparison per matched produced claim; each comparison receives c8.comparisonresult.004 unless a higher §17.2 defect applies;
- every normalized produced claim is consumed by exactly one comparison record;
- no comparison record contains heterogeneous produced claims or hides per-claim defect precedence;
- a produced claim never falls through to `unexpected` merely because its subject/target/locus is more specific than the case-scope prohibition;
- cross-room atomic propositions are first classified under the single precedence model in §9, then matched to c8.claimcode.004 or c8.claimcode.015 as applicable.

Source modes are imported from TDH Rev10. Every eligible RoomCase carries ImageAsset[1..6]. In synthetic-text-only mode, `sourceAssetReference` may be absent and the governed generation/derivation identity is required; the resulting governed asset still has an ImageAsset identity. No sourceAssetReference is fabricated and no ImageAsset is omitted.

## 16. Expected-versus-Produced Claim Comparison

Comparison sequence:

1. bind one concrete evaluation-configuration reference and all mandatory version references from §7.1;
2. seal all allowed expectation records whose predicates are true;
3. seal one prohibited expected-absence record for each of the twelve prohibited codes;
4. obtain and preserve untouched provider/mechanism output;
5. create exactly one immutable RawMechanismAssertionArtifact for each eligible emitted assertion in original output order;
6. assign exactly one c8.assertionnormalizationstatus identity without modifying raw payload;
7. for complete/partial normalization, create one c8.recordtype.003 record per normalized atomic interpretation; for partial/impossible normalization, create exactly one raw-defect comparison with c8.comparisonresult.016;
8. classify every normalized atomic proposition by the single deterministic precedence model in §9;
9. apply the allowed full match key or prohibited code-scoped match key from §12.1;
10. create one comparison per normalized produced claim, plus only the zero-match expectation/prohibition closure comparisons required by §12.1;
11. preserve final-output duplicates, contradictions and all simultaneously true secondary failures; repeated per-view evidence occurrences are provenance, not duplicates;
12. select exactly one primary Contract-8 comparison result for each comparison under §17.2;
13. adjudicate only registered ambiguity/conflict;
14. finalize assertion-linked fail-to-adjudicate as c8.comparisonresult.005 and package-only fail-to-adjudicate as c8.failure.039 without fabricating an emitted assertion;
15. seal final Contract-8 comparisons and package outcomes;
16. deterministically fan in all results belonging to each RawMechanismAssertionArtifact into exactly one ETAPAssertionProjectionFact under §17.3;
17. consume exactly one ETAP `PARTIAL-CLAIM-CONFORM` mechanism-output unit for each final assertion projection and zero units for expectation-only/package-only facts.

Ground truth cannot be derived from provider output. Raw output cannot be copied from ground truth. Evaluator-normalized interpretations cannot overwrite raw assertions. Comparison records cannot replace either side.

### 16.1 Prohibited expectation comparison

For each prohibited code, one sealed RoomCase-scope prohibition record exists before output. Its matching domain is all normalized produced atomic claims in the same RoomCase whose primary code equals the prohibited code. Subject, target and locus are preserved as diagnostics but are not part of the prohibition match key.

A zero-match prohibition receives one absence comparison. Every produced prohibited claim receives its own comparison against the same prohibition record. This preserves per-claim primary/secondary defects and the one-raw-assertion ETAP fan-in; no prohibition comparison aggregates several produced identities.

### 16.2 Multiple simultaneous defects

One normalized atomic claim may satisfy several Contract-8 defect predicates. Its comparison record stores exactly one primary comparison result and zero-to-many secondary failure identities. Primary selection follows §17.2; secondary facts remain auditable. Several atomic claims never share one primary-result slot.

### 16.3 Fault ownership boundary

The following distinctions are mandatory:

- a raw mechanism-emitted wrong code, subject, target, locus, or malformed contract-shaped assertion is a mechanism-output defect;
- an evaluator atomization, normalization, code assignment, subject/target/locus mapping, or transformation-provenance defect invalidates or repairs the evaluation package and is never scored against the mechanism;
- when the raw mechanism output contains no governed code/identity dimension, the evaluator shall not fabricate a raw defect for that absent dimension;
- correction of mutable evaluator artifacts never mutates untouched raw mechanism output;
- category-prior causation is recognized only when the untouched raw assertion payload itself explicitly states category typicality as the sole basis.

### 17.3 Deterministic assertion-level fan-in and ETAP `PARTIAL-CLAIM-CONFORM` projection

ETAP Rev16 remains the sole owner of the metric. Contract 8 defines one deterministic fan-in and projection for each RawMechanismAssertionArtifact.

#### 17.3.1 Fan-in algorithm

Apply the following rules in order:

1. if the evaluation package is invalid because of evaluator, expectation-package, lifecycle, source-authority, or version-bundle defects, no projection is consumable; rebuild is mandatory and no mechanism score is assigned;
2. otherwise, if any linked comparison is c8.comparisonresult.013, select c8.assertionprojectionresult.003 and consume zero ETAP units until adjudication finalizes;
3. otherwise, if normalization status is c8.assertionnormalizationstatus.002 or .003, or a linked raw-defect comparison is c8.comparisonresult.016, select c8.assertionprojectionresult.002;
4. otherwise, if any linked atomic comparison has a final mechanism-attributable FAIL — including .004, assertion-linked .005, .007–.012, .015, .017, or .018 — select c8.assertionprojectionresult.002;
5. otherwise, if normalization status is c8.assertionnormalizationstatus.001, at least one normalized produced claim exists, and every linked atomic comparison is final passing (.001 or .014), select c8.assertionprojectionresult.001;
6. a complete-normalization raw assertion with zero normalized claims, a raw assertion with zero linked comparisons, or any mixed/uncovered state is an invalid evaluation package and cannot default to PASS;
7. mixed child PASS/FAIL always resolves to one final assertion FAIL; all child results remain linked and auditable.

Each normalized produced claim has its own comparison. Therefore heterogeneous defects never compete inside an aggregate comparison, and fan-in is performed only at the RawMechanismAssertionArtifact boundary.

#### 17.3.2 ETAP projection properties

| Projection property | Contract-8 obligation |
|---|---|
| Unit identity | exactly one final ETAPAssertionProjectionFact for each eligible RawMechanismAssertionArtifact |
| Denominator contribution | one for c8.assertionprojectionresult.001 or .002; zero while .003 is pre-final |
| PASS contribution | only c8.assertionprojectionresult.001 |
| FAIL contribution | only c8.assertionprojectionresult.002 |
| Missing required expectation | c8.expectationpackageoutcome.001 and Contract-8 semantic recall FAIL only; zero ETAP units because no assertion was emitted |
| False-predicate expectation | c8.expectationpackageoutcome.002 package FAIL; zero ETAP units |
| Invalid requirement identity | c8.expectationpackageoutcome.003 package FAIL and, when a comparison exists, c8.comparisonresult.006; zero ETAP units |
| Prohibited expected absence | Contract-8 semantic PASS only; zero ETAP units and zero PASS credit |
| Several prohibited assertions | one separate produced-claim comparison per atomic claim; one fan-in projection per originating raw assertion |
| One raw assertion with several atomic propositions | fan in every child; any final failing child makes the single assertion unit FAIL |
| Repeated per-view evidence consolidated into one emitted assertion | one raw assertion and one ETAP unit; no duplicate FAIL |
| Duplicate assertions in final consolidated output | one ETAP unit per raw assertion; duplicate defect attached to each involved assertion comparison |
| Raw normalization impossible | zero produced-claim records, one raw-defect comparison .016, one final assertion FAIL unit |
| Evaluator/package defect | no consumable mechanism projection; invalidate/rebuild package |
| Package-only fail-to-adjudicate | final Contract-8 package FAIL; zero ETAP units because no emitted assertion is affected |
| Assertion-linked fail-to-adjudicate | comparison .005; fan-in final assertion FAIL; one ETAP FAIL unit for each affected raw assertion |

C8EvaluationRecord identities are never ETAP units. The mechanism-output conformance identity is the RawMechanismAssertionArtifact together with its final ETAPAssertionProjectionFact.
